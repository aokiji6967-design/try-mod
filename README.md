# No Friendly Fire (FriendGuard)

Standalone, compilable copy of the mod. Everything Gradle needs to produce the mod
jar is inside this folder.

## What's here

```
no friendly fire/
├── build.gradle              # Fabric Loom build script (MC 1.21.11, Java 21)
├── settings.gradle           # Fabric + Maven repos, rootProject.name
├── gradle.properties         # MC / yarn / loader / fabric-api versions
├── gradlew, gradlew.bat      # Gradle wrapper (9.2.0)
├── gradle/wrapper/           # wrapper jar + properties
├── libs/
│   └── modmenu-17.0.1-beta.1.jar   # compile-time dep referenced by build.gradle
├── src/main/java/            # all mod source
│   └── xyz/lyki/friendguard/
│       ├── FriendGuard.java
│       ├── FriendGuardClient.java
│       ├── Config/{FriendGuardConfigScreen,FriendGuardModMenu}.java
│       └── KeyUtils/{AddRemovePlayer,ClearList}.java
├── src/main/resources/       # fabric.mod.json, friendguard.json (mixins), config, logo
├── docs/                     # tracker analysis notes
└── .github/workflows/build.yml  # GitHub Actions build
```

## Build it locally

Requires **JDK 21**.

```bash
./gradlew build
```

The mod jar lands in `build/libs/friendguard-2.2.2.jar`.
On Windows Git Bash, run `chmod +x gradlew` first if you get a permission error.

## Build it on GitHub

Push this folder as the repository root. `.github/workflows/build.yml` runs
`./gradlew build` on every push and uploads the jar as an artifact named
`friendguard-jar`.

## Deliberately not included

| Excluded | Why |
|----------|-----|
| `build/`, `.gradle/` | generated output, regenerated by Gradle |
| `tools/`, `remapped/` | my local decompiler tooling, not needed to build |
| `friendguard-2.2.2-mc1.21.11.jar` | the original closed-source jar — "All Rights Reserved", must not be redistributed |

The `libs/modmenu-17.0.1-beta.1.jar` file **is** included on purpose: `build.gradle`
depends on it as a local file because `maven.terraformersmc.net` is unreachable here.
If your CI can reach that Maven repo, you can switch to the normal ModMenu dependency.

## Known limitation

The tracker shows direction for every player the client actually receives an entity
for, at any distance, and announces players it cannot locate as being "in another
dimension". It cannot name *which* dimension (Nether/End) because the vanilla client
is never told another player's dimension — see `docs/player-tracker-analysis.md`.
Naming the dimension needs a server-side companion or the server-controlled
locator-bar waypoint API.
